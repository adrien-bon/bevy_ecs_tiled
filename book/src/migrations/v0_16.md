# Migration to `bevy_ecs_tiled` v0.16

This guide outlines the steps required to migrate your project to version `0.16` of `bevy_ecs_tiled`.

This version still targets Bevy v0.20: there is no Bevy upgrade involved, only `bevy_ecs_tiled` API changes.

## Main Changes

- **Dynamic maps:** Tiled data (tiles, objects, images) are now separated from their rendering and physics.
  When loading a map, only Tiled data entities are spawned. Tilemaps, objects visuals, image sprites and physics colliders are derived from them during `PostUpdate`.
  If you spawn, despawn or modify a tile, an object or an image after the map has been loaded, its rendering and colliders are automatically updated.
- **Tiles are direct children of their layer**, next to the tilemaps rendering them.
- **`TilemapCreated` is now a rendering event**, sent whenever a tilemap is spawned.
- **Physics colliders are spawned during `PostUpdate`** and spawned again when their source changes.
- **`TiledMapStorage` stays up to date** when entities are added, modified or removed.

See the [Entities hierarchy](../design/entities_hierarchy.md) page and the [`map_dynamic` example](https://github.com/adrien-bon/bevy_ecs_tiled/blob/main/examples/map_dynamic.rs) for more information.

## Migration Steps

### 1. Update Dependencies

```toml
bevy = "0.20"
bevy_ecs_tiled = "0.16"
```

### 2. Rendering Components and Colliders Are Not Available in `*Created` Events Anymore

`MapCreated`, `LayerCreated`, `TileCreated` and `ObjectCreated` events are still sent once all the map entities have been spawned.
However, they now only hold Tiled data: tilemaps, objects visuals, image sprites and physics colliders do not exist yet when these events are sent.
They are spawned later in the same frame, during the new `TiledPostUpdateSystems::SyncRender` and `TiledPostUpdateSystems::SyncPhysics` system sets.

If you relied on them in a `*Created` event handler, you should instead:

- use `TiledEvent<TilemapCreated>` for tilemaps,
- use `TiledEvent<ColliderCreated>` for physics colliders,
- use an `On<Add<TiledObjectVisualOf>>` observer, or a regular system, for objects visuals and images sprites.

### 3. Tiles Hierarchy

Tiles are no longer children of their `TiledTilemap`: both tiles and tilemaps are now direct children of their `TiledLayer::Tiles`.
Tile entities also have a `TiledMapReference` component.

To retrieve the tilemap of a tile, use its `TilemapId` component instead of its `ChildOf` component:

```rust,ignore
// Before (v0.15)
fn system(tiles: Query<&ChildOf, With<TiledTile>>, tilemaps: Query<&GlobalTransform, With<TiledTilemap>>) {
    for child_of in tiles.iter() {
        let tilemap_transform = tilemaps.get(child_of.parent());
    }
}

// After (v0.16)
fn system(tiles: Query<&TilemapId, With<TiledTile>>, tilemaps: Query<&GlobalTransform, With<TiledTilemap>>) {
    for tilemap_id in tiles.iter() {
        let tilemap_transform = tilemaps.get(tilemap_id.0);
    }
}
```

To retrieve the tilemaps of a layer, you can use the new `TiledTilemaps` relationship (and `TiledTilemapOf` on the tilemap side).

Tilemaps are now automatically despawned when they do not contain any tile anymore: you should not spawn tilemaps yourself.

### 4. `TilemapCreated` Event

`TiledEvent<TilemapCreated>` is now sent during `TiledPostUpdateSystems::SyncRender`, each time a tilemap is spawned: when the map is loaded, but also later on if a tile using a new tileset is added to a layer.
It is no longer sent in order with other `*Created` events and is only sent when the `render` feature is enabled.

### 5. `TiledEvent` Tile Information

`TiledEvent::with_tile()` now takes the tileset ID of the tile:

```rust,ignore
// Before (v0.15)
event.with_tile(tile_entity, tile_pos, tile_id);

// After (v0.16)
event.with_tile(tile_entity, tile_pos, tileset_id, tile_id);
```

`TileCreated` events do not contain tilemap information anymore: `tilemap_entity()` and `tilemap_tileset_id()` return `None`.
Use the new `tile_tileset_id()` accessor instead. `TiledEvent::tile()` keeps working as before.

### 6. `TiledObject::Tile`

`TiledObject::Tile` now holds the tile it references:

```rust,ignore
TiledObject::Tile {
    width: f32,
    height: f32,
    tileset_id: u32,
    tile_id: tiled::TileId,
    flip_x: bool,
    flip_y: bool,
}
```

Since a tile object can reference a tileset which is only used by a template, its tileset ID can be greater than the number of tilesets of the map.
Use the new `TiledMapAsset::tileset()` and `TiledMapAsset::tile()` functions to retrieve the corresponding Tiled data: contrary to `tileset_from_map()` and `tile_from_map()`, they also handle these tilesets.

`TiledObject::from_object_data()` now takes the `TiledMapAsset` as first argument, in order to resolve this tileset ID.

A new `TiledObject::kind()` function returns the object kind as a string.

### 7. Objects Visuals

`TiledObjectVisualOf` no longer requires a `Sprite` component.
It is now also inserted on the `TiledObjectTextBox` entity of text objects.

Visual entities are despawned and spawned again whenever the `TiledObject` component changes.

### 8. `TiledImage`

`TiledImage` now holds all the image data and is not `Copy` anymore:

```rust,ignore
pub struct TiledImage {
    pub image: Handle<Image>,
    pub base_position: Vec2,
    pub base_size: Vec2,
    pub repeat_x: bool,
    pub repeat_y: bool,
}
```

Its `Sprite` is derived from it: to change the image, modify the `TiledImage` component instead of the `Sprite`.

### 9. Physics

- `TiledPreUpdateSystems::SpawnPhysicsColliders` has been removed: colliders are now spawned during `TiledPostUpdateSystems::SyncPhysics`.
- Colliders are computed from the tiles and objects entities instead of the map asset.
  Colliders of a tiles layer are spawned again when one of its tiles is added, modified or removed, and colliders of an object are spawned again when its `TiledObject` component changes.
  As a consequence, you can receive `TiledEvent<ColliderCreated>` several times for the same source.
- Colliders of tiles layers now take tiles flips (horizontal, vertical and diagonal) into account, which was not the case before, and are spawned again when a `TileFlip` changes.
- `TiledEvent<ColliderCreated>::tiles()` still reads tiles from the map asset: it does not take into account modifications made after the map has been loaded.

### 10. Tile Objects Custom Properties

Tile objects now inherit the custom properties of the tile they reference, as in the Tiled editor.
Their own properties take precedence over the tile ones.

Tile properties are also inserted on tiles and tile objects spawned after the map has been loaded.

### 11. New System Sets

`TiledPostUpdateSystems` has three new variants, which run in this order after `HandleMapAssetEvents`:

- `SyncMapStorage`: registers new or modified tiles in `TiledMapStorage`,
- `SyncRender`: spawns or updates tilemaps, objects visuals and images sprites,
- `SyncPhysics`: spawns or updates physics colliders.

`SyncRender` and `SyncPhysics` run before Bevy transform and visibility propagation.
If you modify Tiled data and want the result to be visible in the same frame, do it before `PostUpdate`.

# Migration to `bevy_ecs_tiled` v0.16

This guide outlines the steps required to migrate your project to version `0.16` of `bevy_ecs_tiled`.

This version still targets Bevy v0.20: there is no Bevy upgrade involved, only `bevy_ecs_tiled` API changes.

## Main Changes

- **Dynamic maps:** a map can now be modified after it has been loaded. Tilemaps, objects visuals, image sprites and physics colliders are derived from tiles, objects and images entities during `PostUpdate`.
  See the [Modify a map at runtime](../guides/dynamic_maps.md) guide and the [`map_dynamic` example](https://github.com/adrien-bon/bevy_ecs_tiled/blob/main/examples/map_dynamic.rs).
- **Tiles are direct children of their layer**, next to the tilemaps rendering them.
- **Tileset, layer and object IDs** are no longer standalone components, and IDs now have dedicated types.

## Migration Steps

### 1. Update Dependencies

```toml
bevy = "0.20"
bevy_ecs_tiled = "0.16"
```

### 2. Derived Entities Do Not Exist in `*Created` Events

`MapCreated`, `LayerCreated`, `TileCreated` and `ObjectCreated` events are now sent before tilemaps, objects visuals, image sprites and physics colliders are spawned.
These are spawned later in the same frame, in `PostUpdate`. If you relied on them in one of these event handlers:

- use `TiledEvent<TilemapCreated>` for tilemaps,
- use `TiledEvent<ColliderCreated>` for physics colliders,
- use an `On<Add<TiledObjectVisualOf>>` observer, or a regular system, for objects visuals,
- use a regular system, running after `TiledPostUpdateSystems::SyncRender`, for image sprites.

Do not modify derived components, such as the `Sprite` of an image: they are overwritten when their source changes.

### 3. Tiles Hierarchy

Tiles are no longer children of their `TiledTilemap`: both are now direct children of their `TiledLayer::Tiles`.
To retrieve the tilemap of a tile, use its `TilemapId` component instead of its `ChildOf` component:

```rust,ignore
// Before (v0.15)
fn system(tiles: Query<&ChildOf, With<TiledTile>>, tilemaps: Query<&GlobalTransform, With<TiledTilemap>>) {
    for child_of in tiles.iter() {
        let tilemap_transform = tilemaps.get(child_of.parent());
    }
}

// After (v0.16)
fn system(tiles: Query<&TilemapId, With<TiledTile>>, tilemaps: Query<&GlobalTransform, With<TiledTilemap>>) {
    for tilemap_id in tiles.iter() {
        let tilemap_transform = tilemaps.get(tilemap_id.0);
    }
}
```

Tilemaps are created when needed and despawned once empty: you should not spawn them yourself.

### 4. Tiles and Tilemaps IDs

The `TiledTilesetId` and `TiledTileId` components have been removed: these IDs are now fields of the `TiledTile` and `TiledTilemap` components.

```rust,ignore
// Before (v0.15)
fn system(tiles: Query<(&TiledTilesetId, &TiledTileId), With<TiledTile>>) { /* ... */ }

// After (v0.16)
fn system(tiles: Query<&TiledTile>) { /* tile.tileset_id, tile.tile_id */ }
```

Use `Changed<TiledTile>` instead of `Changed<TiledTilesetId>` / `Changed<TiledTileId>`.

### 5. Layers and Objects IDs

The `TiledLayerId` and `TiledObjectId` components have been removed, along with the APIs relying on them:

| Removed | Replacement |
| --- | --- |
| `TiledEvent::layer_id()`, `object_id()` | `layer_entity()`, `object_entity()` |
| `TiledEvent::layer()`, `object()` | query the components of the layer or object entity |
| `TiledMapStorage::layer_entity()`, `layer_id()`, `layer()` | iterate over `TiledMapStorage::layers()` |
| `TiledMapStorage::object_entity()`, `object_id()`, `object()` | iterate over `TiledMapStorage::objects()` |
| `TiledMapStorage::tile_id()`, `tile()` | the `TiledTile` component of the tile entity, and `TiledMapAsset::tile()` |

`TiledMapStorage::layers()` and `objects()` now yield entities only.

To read the class or custom properties of the map, a layer or an object, use the new `TiledProperties` component, which is available even without the `user_properties` feature:

```rust,ignore
// Before (v0.15)
fn on_object(event: On<TiledEvent<ObjectCreated>>, assets: Res<Assets<TiledMapAsset>>) {
    let Some(object) = event.event().object(&assets) else { return };
    info!("{:?}", object.properties);
}

// After (v0.16)
fn on_object(event: On<TiledEvent<ObjectCreated>>, objects: Query<&TiledProperties>) {
    let Ok(properties) = objects.get(event.origin) else { return };
    info!("{} {:?}", properties.class, properties.properties);
}
```

### 6. Dedicated ID Types

IDs are not plain `u32` anymore. The tile ID is still a `tiled::TileId`.

| Type | ID | Main APIs |
| --- | --- | --- |
| `TilesetId` | tileset of a map | `TiledTile`, `TiledTilemap`, `TiledObject::Tile`, `TiledMapStorage::tiles()`, `tile_entities()`, `TiledEvent::with_tilemap()`, `tilemap_tileset_id()`, `TiledMapAsset::tileset()`, `TiledMapAsset::tile()` |
| `LayerId` | Tiled layer ID | `TiledMapAsset::layer()` |
| `ObjectId` | Tiled object ID | `TiledMapAsset::object()` |
| `WorldMapId` | index of a map in its `.world` file | `TiledWorldStorage::maps()`, `map_entity()`, `map_id()` |

Wrap the raw value to build an ID, and use `.0` or `u32::from()` to read it:

```rust,ignore
// Before (v0.15)
let tileset = tileset_from_map(&map_asset.map, 0);
let layer = layer_from_map(&map_asset.map, 3);
let map_entity = world_storage.map_entity(1);

// After (v0.16)
let tileset = map_asset.tileset(TilesetId(0));
let layer = map_asset.layer(LayerId(3));
let map_entity = world_storage.map_entity(WorldMapId(1));
```

#### Map helper functions

Helper functions taking a `tiled::Map` have been replaced by methods and fields of `TiledMapAsset`, which also handle tilesets only used by object templates:

| Before | After |
| --- | --- |
| `tileset_from_map(&map_asset.map, id)` | `map_asset.tileset(id)` |
| `tile_from_map(&map_asset.map, tileset_id, tile_id)` | `map_asset.tile(tileset_id, tile_id)` |
| `layer_from_map(&map_asset.map, id)` | `map_asset.layer(id)` |
| `object_from_map(&map_asset.map, id)` | `map_asset.object(id)` |
| `tilemap_type_from_map(&map_asset.map)` | `map_asset.map_type` |
| `try_tilemap_type_from_map(&map)` | removed: maps with an unsupported orientation fail to load |
| `grid_size_from_map(&map_asset.map)` | `map_asset.grid_size` |

`TiledMapAsset::layer()` also finds group layers, which `layer_from_map()` did not.

### 7. `TiledEvent`

- `TiledEvent` can no longer be built nor sent from outside the crate: `new()`, `with_event()` (previously `transmute()`), `with_world()`, `with_map()`, `with_layer()`, `with_tilemap()`, `with_tile()`, `with_object()` and `send()` are now private. If you sent your own `TiledEvent`s, define your own event type instead.
- New `is_original()` method: events bubble up the entity hierarchy and a global observer (added with `App::add_observer`) runs once for each entity the event bubbles through. Use `if !event.is_original() { return; }` to only handle each event once.
- `TileCreated` events do not hold tilemap information anymore: `tilemap_entity()` and `tilemap_tileset_id()` return `None`. Use `tile_tileset_id()` instead.
- `TilemapCreated` is sent each time a tilemap is spawned, including after the map has been loaded, and only with the `render` feature. It is no longer ordered with other `*Created` events.
- `TiledEvent` is no longer a `Component`.
- The type parameter of `TiledEvent<E>` is now bound by the new sealed `TiledEventKind` trait, implemented by all event kinds of the crate: replace `E: Debug + Clone + Copy + Reflect` by `E: TiledEventKind` in your generic code.
- `TileCreated` has been renamed `TileWithPropertiesCreated`: as before, it is only sent for tiles with custom properties, when the map is loaded.

### 8. `TiledObject` and Objects Visuals

- `TiledObject::center()`, `vertices()`, `line_string()` and `polygon()` are no longer public: use `TiledMapAsset::object_center()`, `object_vertices()`, `object_line_string()` and `object_polygon()`, which only need the object and its `GlobalTransform`.
- `TiledObject::Text::font_size` is now a `f32`.

`TiledObject::Tile` now holds the tile it references:

```rust,ignore
TiledObject::Tile {
    width: f32,
    height: f32,
    tileset_id: TilesetId,
    tile_id: tiled::TileId,
    flip_x: bool,
    flip_y: bool,
}
```

Use `TiledMapAsset::tileset()` and `TiledMapAsset::tile()` to read the corresponding Tiled data: its tileset can be only used by a template, which is not part of the `tiled::Map` tilesets.

`TiledObject::from_object_data()` now takes the `TiledMapAsset` as first argument.

`TiledObjectVisualOf` no longer requires a `Sprite`, and is also inserted on the `TiledObjectTextBox` of text objects: do not assume that a visual entity has a `Sprite`.

### 9. `TiledImage`

`TiledImage` now holds all the image data and is not `Copy` anymore:

```rust,ignore
pub struct TiledImage {
    pub image: Handle<Image>,
    pub base_position: Vec2,
    pub base_size: Vec2,
    pub repeat_x: bool,
    pub repeat_y: bool,
}
```

To change the image, modify this component instead of the `Sprite`.

The `image` field only exists with the `render` feature.

### 10. Physics

- `TiledPreUpdateSystems::SpawnPhysicsColliders` has been removed: use `TiledPostUpdateSystems::SyncPhysics`.
- Colliders are spawned again when their source changes: you can receive `TiledEvent<ColliderCreated>` several times for the same source.
- `TiledEvent<ColliderCreated>::tiles()` has been removed: query the `TiledTile` children of the layer instead (`TiledTile`, `TilePos`, `TileFlip`).
- `ColliderCreated::collider_of` and `ColliderCreated::new()` have been removed: the event origin is the collider entity, use `TiledEvent::layer_entity()` or `TiledEvent::object_entity()` (depending on `ColliderCreated::source`) to retrieve the layer or object the collider is created for, or query the `TiledColliderOf` component of the collider entity.
- Colliders of tiles layers now take tiles flips into account, which can change their shape.

- Modifying `TiledPhysicsSettings` no longer respawns the map or the world: only physics colliders are spawned again.

#### Collider strategy

How colliders are created from Tiled shapes is no longer selected by the physics backend: `TiledPhysicsAvianBackend` and `TiledPhysicsRapierBackend` are now unit structs, and their variants moved to the new `TiledColliderStrategy` enum, set in `TiledPhysicsSettings`:

```rust,ignore
// Before
TiledPhysicsSettings::<TiledPhysicsAvianBackend> {
    backend: TiledPhysicsAvianBackend::Triangulation,
    ..default()
}

// After
TiledPhysicsSettings::<TiledPhysicsAvianBackend> {
    collider_strategy: TiledColliderStrategy::Triangulation,
    ..default()
}
```

`TiledColliderStrategy` is also a component: insert it on a layer or an object entity to override the map strategy for this layer or object only.

#### Custom physics backends

The `TiledPhysicsBackend` trait no longer spawns entities: it only creates the colliders for a given geometry, and `bevy_ecs_tiled` inserts them on the right entities and removes them when their source changes.

```rust,ignore
// Before
impl TiledPhysicsBackend for MyBackend {
    fn spawn_colliders(
        &self,
        commands: &mut Commands,
        source: TiledColliderSource,
        origin: Entity,
        multi_polygons_list: Vec<geo::MultiPolygon<f32>>,
    ) -> Option<Entity> {
        /* spawn an entity with a collider */
    }
}

// After
impl TiledPhysicsBackend for MyBackend {
    // The component(s) making a collider
    type Collider = MyCollider;

    fn colliders(
        &self,
        strategy: TiledColliderStrategy,
        source: TiledColliderSource,
        geometry: &geo::MultiPolygon<f32>,
    ) -> Vec<Self::Collider> {
        /* return the collider(s) for this geometry */
    }
}
```

- `colliders()` is called once for each geometry: a single time if geometry simplification is enabled (the default).
- The new `collider_shapes()` helper converts a geometry into `TiledColliderShape`s according to the requested strategy.
- If you need access to the `World` to build your collider (eg. to add an asset), use component hooks or observers on your collider component: see the [`physics_custom` example](https://github.com/adrien-bon/bevy_ecs_tiled/blob/main/examples/physics_custom.rs).
- `multi_polygon_as_line_strings()` now returns an iterator over borrowed line strings instead of a `Vec`.

### 10b. Prelude

The prelude no longer contains advanced items. Import them from their module instead:

- the `geo` and `regex` crates are re-exported at the crate root: `use bevy_ecs_tiled::{geo, regex};` instead of `bevy_ecs_tiled::prelude::{geo, regex}`,
- `collider_shapes()`, `multi_polygon_as_line_strings()`, `multi_polygon_as_triangles()` and `TiledColliderShape`, mainly used to write a custom physics backend: `use bevy_ecs_tiled::physics::geometry::*;`,
- `tiled_debug_gizmos_enabled()`: `use bevy_ecs_tiled::debug::tiled_debug_gizmos_enabled;`.

### 10d. Chunking and Streaming Components

`TiledWorldChunking` has been renamed `TiledWorldStreaming`, to avoid confusion with physics colliders chunks and infinite maps chunks. Accordingly:

- the `world::chunking` module is now `world::streaming`,
- `TiledPostUpdateSystems::HandleWorldChunking` is now `TiledPostUpdateSystems::HandleWorldStreaming`,
- `TiledDebugWorldChunkPlugin` and `TiledDebugWorldChunkConfig` are now `TiledDebugWorldStreamingPlugin` and `TiledDebugWorldStreamingConfig`, whose `world_chunk_color` field is now `streaming_area_color`,
- the `world_chunking` example is now `world_streaming`.

`TiledColliderChunkSize` and `TiledWorldStreaming` are now enums instead of wrappers around an `Option`, and `TiledPhysicsSettings::tiles_chunk_size` is a `TiledColliderChunkSize`:

```rust,ignore
// Before
TiledColliderChunkSize(None)
TiledColliderChunkSize(Some(UVec2::splat(16)))
TiledPhysicsSettings { tiles_chunk_size: Some(UVec2::splat(16)), .. }
TiledWorldChunking(None)
let area: Option<Vec2> = world_chunking.0;

// After
TiledColliderChunkSize::Disabled
TiledColliderChunkSize::new(16, 16) // or TiledColliderChunkSize::Size(UVec2::splat(16))
TiledPhysicsSettings { tiles_chunk_size: TiledColliderChunkSize::new(16, 16), .. }
TiledWorldStreaming::Disabled
let area: Option<Vec2> = world_streaming.area();
```

`TiledWorldStreaming::new()` works as `TiledWorldChunking::new()` did. If you set these components from Tiled custom properties, export your types again and update the properties.

### 10e. Map Helpers

- `tile_size()` is no longer public: use `TiledMapAsset::tile_size(&TiledTile)`.
- `TiledMapAsset::tile_relative_position()` takes the `TiledTile` instead of its size, and returns an `Option<Vec2>` (`None` if the tile does not exist in the map).
- New `TiledMapHelper` system parameter, which retrieves the map asset and anchor of any Tiled entity: `maps.map(entity)`, `maps.tile_relative_position(tile_entity)`.
- `TiledLayerParallax::parallax_x` and `parallax_y` are merged into `parallax: Vec2`.
- `TiledObject::kind()` has been removed: `TiledObject` implements `Display` instead (`format!("{object}")`).

### 10c. Non-Exhaustive Enums

`TiledObject`, `TiledColliderStrategy`, `TiledColliderShape` and the `TiledPreUpdateSystems`, `TiledUpdateSystems` and `TiledPostUpdateSystems` system sets are now `#[non_exhaustive]`, so new variants can be added without a breaking change: add a wildcard arm (`_ => ...`) when matching on them. A custom physics backend which does not support a new `TiledColliderStrategy` can fall back to another one.

#### Colliders entities

- The first collider of a tiles layer or an object is always inserted on the layer or object entity itself. This was already the case with the provided backends.
- Additional colliders (`TiledColliderStrategy::LineStrip`, or geometry simplification disabled) are children of this entity, named `TiledCollider(<index>)` instead of `Avian[...]` / `Rapier[...]`. They now also have the `TiledColliderOf`, `TiledColliderSource` and `TiledColliderPolygons` components, and a `TiledEvent<ColliderCreated>` is sent for each of them.
- `TiledColliderPolygons` holds the geometry of its own collider only.

### 11. System Sets

`TiledPostUpdateSystems` has three new variants, which run in this order after `HandleMapAssetEvents` and before Bevy transform and visibility propagation: `SyncMapStorage`, `SyncRender` and `SyncPhysics`.

If you order your systems against map rendering or colliders, use these sets.

`TiledUpdateSystems::UpdateTiledImagePositionAndSize` has been removed: repeated images position and size are updated during `TiledPostUpdateSystems::SyncRender`.

### 11b. Plugin Configuration and Filters

- `TiledPluginConfig` has been removed: its fields are now directly on `TiledPlugin`, only with the `user_properties` feature, and are renamed: `tiled_types_export_file` becomes `types_export_file` and `tiled_types_filter` becomes `types_filter`.
- **Types are no longer exported by default**: set `types_export_file` to keep exporting them.

```rust,ignore
// Before
App::new().add_plugins(TiledPlugin(TiledPluginConfig {
    tiled_types_export_file: Some(path),
    tiled_types_filter: filter,
}));

// After
App::new().add_plugins(TiledPlugin {
    types_export_file: Some(path),
    types_filter: filter,
});
```

- `simplify_geometry()` has been removed: use [`geo::unary_union`](https://docs.rs/geo/latest/geo/algorithm/bool_ops/fn.unary_union.html) to merge polygons. The `TiledPhysicsSettings::simplify_geometry` setting is unchanged.
- A `TiledFilter` can be built from an array or a `Vec` of names (`TiledFilter::from(["wall", "ground"])`), or collected from any iterator of names.
- `TiledName::matches()` has been removed: use `filter.matches(&name.0)` instead.

### 12. Custom Properties

With the `user_properties` feature:

- tile objects now inherit the custom properties of their tile, as in the Tiled editor. Their own properties take precedence,
- tile properties are also inserted on tiles and tile objects spawned after the map has been loaded. Object references in these properties cannot be resolved: they are set to `Entity::PLACEHOLDER`.

---

### 13. Running Without the `render` Feature

Without the `render` feature, nothing is displayed and images and texture atlas layouts are no longer loaded, so a map can be loaded on a headless server. It only requires this minimal set of plugins:

```rust,ignore
App::new().add_plugins((
    MinimalPlugins,
    AssetPlugin::default(),
    TiledPlugin::default(),
));
```

You can remove `ImagePlugin` and `TextureAtlasPlugin` if you only added them for `bevy_ecs_tiled`.

Objects no longer have any visual, tile sprite or text, image layers no longer have a `Sprite` and `TiledAnimation` does not exist: if you displayed them without the `render` feature, enable it.
The `TiledObject` and `TiledImage` entities are still spawned with their data, including the content of text objects.

The `text` and `debug` features now enable the `render` feature: disable them too to run without it.

### 14. The `world` Feature

Tiled worlds (`.world` files) support is now behind the `world` feature. It is enabled by default, so there is nothing to do if you use the default features.

If you disable default features and use Tiled worlds, enable it explicitly:

```toml
bevy_ecs_tiled = { version = "0.16", default-features = false, features = ["render", "world"] }
```

Without this feature, the following APIs do not exist: `TiledWorld`, `RespawnTiledWorld`, `TiledWorldAsset`, `TiledWorldStreaming`, `TiledWorldStorage`, `WorldMapId`, `TiledWorldLoaderError`, `TiledEvent<WorldCreated>`, `world_entity()`, `world_asset()`, `world()` and, with the `debug` feature, `TiledDebugWorldStreamingPlugin`.

### 15. Module Layout

The `bevy_ecs_tiled::tiled` module has been split by layer: `asset` (loading Tiled files), `ecs` (entities holding Tiled data), `render` (rendering derived from these entities, with the `render` feature) and `properties`.
Nothing changes if you only use the prelude, except that rendering components (`TiledTilemap`, `TiledTilemapOf`, `TiledTilemaps`, `TiledObjectVisualOf`, `TiledObjectVisuals`, `TiledObjectTextBox` and `TiledObjectText`) do not exist anymore without the `render` feature. Otherwise, update your paths:

| Before | After |
| --- | --- |
| `tiled::TiledPlugin` | `TiledPlugin` (crate root) |
| `tiled::sets::*` | `sets::*` |
| `tiled::map::asset::TiledMapAsset` | `asset::map::TiledMapAsset` |
| `tiled::map::loader::TiledMapLoaderError` | `asset::map::TiledMapLoaderError` |
| `tiled::world::asset::TiledWorldAsset` | `asset::world::TiledWorldAsset` |
| `tiled::world::loader::TiledWorldLoaderError` | `asset::world::TiledWorldLoaderError` |
| `tiled::layer::LayerId`, `tiled::tile::TilesetId`, `tiled::object::ObjectId`, `tiled::world::storage::WorldMapId` | `asset::{LayerId, TilesetId, ObjectId, WorldMapId}` |
| `tiled::{map, world, layer, tile, object, image, event, filter}::*` | `ecs::{map, world, layer, tile, object, image, event, filter}::*` |
| `tiled::animation::TiledAnimation` | `render::animation::TiledAnimation` |
| `tiled::tile::{TiledTilemap, TiledTilemapOf, TiledTilemaps}` | `render::tilemap::{TiledTilemap, TiledTilemapOf, TiledTilemaps}` |
| `tiled::object::{TiledObjectVisualOf, TiledObjectVisuals, TiledObjectTextBox, TiledObjectText}` | `render::object::{TiledObjectVisualOf, TiledObjectVisuals, TiledObjectTextBox, TiledObjectText}` |
| `tiled::properties_raw::TiledProperties` | `properties::TiledProperties` |
| `tiled::properties::export_types` | `properties::export_types` |
| `prelude::tiled` (the `tiled` crate) | `bevy_ecs_tiled::tiled` |

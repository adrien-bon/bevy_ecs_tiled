# Migration to `bevy_ecs_tiled` v0.16

This guide outlines the steps required to migrate your project to version `0.16` of `bevy_ecs_tiled`.

This version still targets Bevy v0.20: there is no Bevy upgrade involved, only `bevy_ecs_tiled` API changes.

## Main Changes

- **Dynamic maps:** a map can now be modified after it has been loaded. Tilemaps, objects visuals, image sprites and physics colliders are derived from tiles, objects and images entities during `PostUpdate`.
  See the [Modify a map at runtime](../guides/dynamic_maps.md) guide and the [`map_dynamic` example](https://github.com/adrien-bon/bevy_ecs_tiled/blob/main/examples/map_dynamic.rs).
- **Tiles are direct children of their layer**, next to the tilemaps rendering them.
- **Tileset, layer and object IDs** are no longer standalone components, and IDs now have dedicated types.

## Migration Steps

### 1. Update Dependencies

```toml
bevy = "0.20"
bevy_ecs_tiled = "0.16"
```

### 2. Derived Entities Do Not Exist in `*Created` Events

`MapCreated`, `LayerCreated`, `TileCreated` and `ObjectCreated` events are now sent before tilemaps, objects visuals, image sprites and physics colliders are spawned.
These are spawned later in the same frame, in `PostUpdate`. If you relied on them in one of these event handlers:

- use `TiledEvent<TilemapCreated>` for tilemaps,
- use `TiledEvent<ColliderCreated>` for physics colliders,
- use an `On<Add<TiledObjectVisualOf>>` observer, or a regular system, for objects visuals,
- use a regular system, running after `TiledPostUpdateSystems::SyncRender`, for image sprites.

Do not modify derived components, such as the `Sprite` of an image: they are overwritten when their source changes.

### 3. Tiles Hierarchy

Tiles are no longer children of their `TiledTilemap`: both are now direct children of their `TiledLayer::Tiles`.
To retrieve the tilemap of a tile, use its `TilemapId` component instead of its `ChildOf` component:

```rust,ignore
// Before (v0.15)
fn system(tiles: Query<&ChildOf, With<TiledTile>>, tilemaps: Query<&GlobalTransform, With<TiledTilemap>>) {
    for child_of in tiles.iter() {
        let tilemap_transform = tilemaps.get(child_of.parent());
    }
}

// After (v0.16)
fn system(tiles: Query<&TilemapId, With<TiledTile>>, tilemaps: Query<&GlobalTransform, With<TiledTilemap>>) {
    for tilemap_id in tiles.iter() {
        let tilemap_transform = tilemaps.get(tilemap_id.0);
    }
}
```

Tilemaps are created when needed and despawned once empty: you should not spawn them yourself.

### 4. Tiles and Tilemaps IDs

The `TiledTilesetId` and `TiledTileId` components have been removed: these IDs are now fields of the `TiledTile` and `TiledTilemap` components.

```rust,ignore
// Before (v0.15)
fn system(tiles: Query<(&TiledTilesetId, &TiledTileId), With<TiledTile>>) { /* ... */ }

// After (v0.16)
fn system(tiles: Query<&TiledTile>) { /* tile.tileset_id, tile.tile_id */ }
```

Use `Changed<TiledTile>` instead of `Changed<TiledTilesetId>` / `Changed<TiledTileId>`.

### 5. Layers and Objects IDs

The `TiledLayerId` and `TiledObjectId` components have been removed, along with the APIs relying on them:

| Removed | Replacement |
| --- | --- |
| `TiledEvent::layer_id()`, `object_id()` | `layer_entity()`, `object_entity()` |
| `TiledEvent::layer()`, `object()` | query the components of the layer or object entity |
| `TiledMapStorage::layer_entity()`, `layer_id()`, `layer()` | iterate over `TiledMapStorage::layers()` |
| `TiledMapStorage::object_entity()`, `object_id()`, `object()` | iterate over `TiledMapStorage::objects()` |
| `TiledMapStorage::tile_id()`, `tile()` | the `TiledTile` component of the tile entity, and `TiledMapAsset::tile()` |

`TiledMapStorage::layers()` and `objects()` now yield entities only.

To read the class or custom properties of the map, a layer or an object, use the new `TiledProperties` component, which is available even without the `user_properties` feature:

```rust,ignore
// Before (v0.15)
fn on_object(event: On<TiledEvent<ObjectCreated>>, assets: Res<Assets<TiledMapAsset>>) {
    let Some(object) = event.event().object(&assets) else { return };
    info!("{:?}", object.properties);
}

// After (v0.16)
fn on_object(event: On<TiledEvent<ObjectCreated>>, objects: Query<&TiledProperties>) {
    let Ok(properties) = objects.get(event.event().origin) else { return };
    info!("{} {:?}", properties.class, properties.properties);
}
```

### 6. Dedicated ID Types

IDs are not plain `u32` anymore. The tile ID is still a `tiled::TileId`.

| Type | ID | Main APIs |
| --- | --- | --- |
| `TilesetId` | tileset of a map | `TiledTile`, `TiledTilemap`, `TiledObject::Tile`, `TiledMapStorage::tiles()`, `tile_entities()`, `TiledEvent::with_tilemap()`, `tilemap_tileset_id()`, `tileset_from_map()`, `tile_from_map()` |
| `LayerId` | Tiled layer ID | `layer_from_map()` |
| `ObjectId` | Tiled object ID | `object_from_map()` |
| `WorldMapId` | index of a map in its `.world` file | `TiledWorldStorage::maps()`, `map_entity()`, `map_id()` |

Wrap the raw value to build an ID, and use `.0` or `u32::from()` to read it:

```rust,ignore
// Before (v0.15)
let tileset = tileset_from_map(&map_asset.map, 0);
let layer = layer_from_map(&map_asset.map, 3);
let map_entity = world_storage.map_entity(1);

// After (v0.16)
let tileset = tileset_from_map(&map_asset.map, TilesetId(0));
let layer = layer_from_map(&map_asset.map, LayerId(3));
let map_entity = world_storage.map_entity(WorldMapId(1));
```

### 7. `TiledEvent`

- `with_tile()` also takes the tileset ID of the tile: `event.with_tile(tile_entity, tile_pos, tileset_id, tile_id)`.
- `with_layer()` and `with_object()` only take the entity.
- `TileCreated` events do not hold tilemap information anymore: `tilemap_entity()` and `tilemap_tileset_id()` return `None`. Use `tile_tileset_id()` instead.
- `TilemapCreated` is sent each time a tilemap is spawned, including after the map has been loaded, and only with the `render` feature. It is no longer ordered with other `*Created` events.

### 8. `TiledObject` and Objects Visuals

`TiledObject::Tile` now holds the tile it references:

```rust,ignore
TiledObject::Tile {
    width: f32,
    height: f32,
    tileset_id: TilesetId,
    tile_id: tiled::TileId,
    flip_x: bool,
    flip_y: bool,
}
```

Use `TiledMapAsset::tileset()` and `TiledMapAsset::tile()` to read the corresponding Tiled data: its tileset can be only used by a template, which `tileset_from_map()` and `tile_from_map()` do not handle.

`TiledObject::from_object_data()` now takes the `TiledMapAsset` as first argument.

`TiledObjectVisualOf` no longer requires a `Sprite`, and is also inserted on the `TiledObjectTextBox` of text objects: do not assume that a visual entity has a `Sprite`.

### 9. `TiledImage`

`TiledImage` now holds all the image data and is not `Copy` anymore:

```rust,ignore
pub struct TiledImage {
    pub image: Handle<Image>,
    pub base_position: Vec2,
    pub base_size: Vec2,
    pub repeat_x: bool,
    pub repeat_y: bool,
}
```

To change the image, modify this component instead of the `Sprite`.

The `image` field only exists with the `render` feature.

### 10. Physics

- `TiledPreUpdateSystems::SpawnPhysicsColliders` has been removed: use `TiledPostUpdateSystems::SyncPhysics`.
- Colliders are spawned again when their source changes: you can receive `TiledEvent<ColliderCreated>` several times for the same source.
- `TiledEvent<ColliderCreated>::tiles()` has been removed: query the `TiledTile` children of the layer instead (`TiledTile`, `TilePos`, `TileFlip`).
- Colliders of tiles layers now take tiles flips into account, which can change their shape.
- With a custom `TiledPhysicsBackend`, spawn colliders on a dedicated child entity: colliders inserted on `origin` are only replaced the next time `spawn_colliders()` is called, and are not removed if the source does not produce any collider anymore.

### 11. System Sets

`TiledPostUpdateSystems` has three new variants, which run in this order after `HandleMapAssetEvents` and before Bevy transform and visibility propagation: `SyncMapStorage`, `SyncRender` and `SyncPhysics`.

If you order your systems against map rendering or colliders, use these sets.

### 12. Custom Properties

With the `user_properties` feature:

- tile objects now inherit the custom properties of their tile, as in the Tiled editor. Their own properties take precedence,
- tile properties are also inserted on tiles and tile objects spawned after the map has been loaded. Object references in these properties cannot be resolved: they are set to `Entity::PLACEHOLDER`.

---

### 13. Running Without the `render` Feature

Without the `render` feature, nothing is displayed and images and texture atlas layouts are no longer loaded, so a map can be loaded on a headless server. It only requires this minimal set of plugins:

```rust,ignore
App::new().add_plugins((
    MinimalPlugins,
    AssetPlugin::default(),
    TiledPlugin::default(),
));
```

You can remove `ImagePlugin` and `TextureAtlasPlugin` if you only added them for `bevy_ecs_tiled`.

Objects no longer have any visual, tile sprite or text, image layers no longer have a `Sprite` and `TiledAnimation` does not exist: if you displayed them without the `render` feature, enable it.
The `TiledObject` and `TiledImage` entities are still spawned with their data, including the content of text objects.

The `text` and `debug` features now enable the `render` feature: disable them too to run without it.

### 14. The `world` Feature

Tiled worlds (`.world` files) support is now behind the `world` feature. It is enabled by default, so there is nothing to do if you use the default features.

If you disable default features and use Tiled worlds, enable it explicitly:

```toml
bevy_ecs_tiled = { version = "0.16", default-features = false, features = ["render", "world"] }
```

Without this feature, the following APIs do not exist: `TiledWorld`, `RespawnTiledWorld`, `TiledWorldAsset`, `TiledWorldChunking`, `TiledWorldStorage`, `WorldMapId`, `TiledWorldLoaderError`, `TiledEvent<WorldCreated>`, `TiledEvent::with_world()`, `world_entity()`, `world_asset()`, `world()` and, with the `debug` feature, `TiledDebugWorldChunkPlugin`.
